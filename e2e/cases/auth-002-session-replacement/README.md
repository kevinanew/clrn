# AUTH-002：不同设备再次登录

## 目的与前置条件

P0；线上 staging；桌面及手机；已存在的测试账号；两个独立上下文、不同随机 deviceId。
只登录并读取账户，不创建账号或修改业务数据。会使该测试账号的其他登录会话失效。

## 步骤与预期

| 操作 | 预期 |
| --- | --- |
| A 登录，保存内存中的凭据并读取账户 | HTTP 200 |
| B 用同一账号再次登录 | 登录成功且账户 ID 相同 |
| 分别用 A、B 的凭据读取账户 | A 返回 401，B 返回 200 |
| 再次读取 B 的账户 | 仍返回 200 |

## 定位契约

登录使用当前可见页面的 `hall-sign-in-button`、`username-or-email-sign-in-button`、
`username-input`、`password-input`、`sign-in-button`、`hall-auth-state-signed-in`。
认证通过 `/v11/user/<id>/account` 验证，不能仅凭缓存或头像可见判断有效。

## 关联问题

2026-09-26 在指定线上站点实测：B 登录后 A 立即返回 401，5 秒后仍为 401。
新会话为 200。该结论针对不同设备重复登录；不是“账号只能使用一次”。
网络错误、5xx 与超时不会当作旧会话正常失效。报告不记录 token 或原始账户响应。
