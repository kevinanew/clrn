# PRIVATE-003：第二账号加入私人牌局

## 目的与前置条件

P1，已部署 staging，桌面和手机。需要创建专用房主账号、`TESTING_API_TOKEN` 和可用的测试注册接口。每例另创建一个独立加入者账号；房主由创建 fixture 初始化为 60 钻。

## 步骤与预期

| 操作 | 预期 |
| --- | --- |
| 房主创建私人德州牌局并退出牌桌 | 创建响应给出本次 UUID，牌桌等待开始，扣 10 钻，私人房中保留牌局 |
| 读取房主九位房号，加入者从私人房入口填写并提交 | 进入同名、私人房类型的真实牌桌，状态为等待开始 |
| 加入者退出，房主删除本次牌局 | 真实 DELETE 成功，房主退回 10 钻 |

## 定位契约

使用 `copy-house-number-button`、`personal-house-join`、`personal-room-smooth-pin-code-input`、`join-game-button`、`run-game-view` 和牌桌名称、类型、状态 test ID。当前可见页面目标均验证唯一性。房号来自房主页面，不使用固定号码；牌局 UUID 来自真实创建响应。

## 关联问题

该案例验证第二账号进入牌桌，不覆盖入座、开始、下注或结算。即使加入断言失败，也只删除本次创建响应捕获的牌局。测试账号保留在 staging，浏览器状态只存于本轮内存。需配置创建专用账号；缺失时案例明确失败，不计作通过。
