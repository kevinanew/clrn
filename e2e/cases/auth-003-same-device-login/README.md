# AUTH-003：相同设备标识再次登录

## 目的与前置条件

P0；线上 staging；桌面及手机；已存在的测试账号。
两个隔离上下文使用相同随机 deviceId，但分别通过真实登录签发凭据。

## 步骤与预期

| 操作 | 预期 |
| --- | --- |
| A 登录并请求账户 | HTTP 200 |
| 同一 deviceId 的 B 再次登录同一账号 | HTTP 200 且账户一致 |
| 分别请求账户 | A 为 401，B 仍为 200 |

## 定位契约

与 AUTH-002 相同，使用 `_shared/auth.ts` 中的真实 UI 登录与只读账户请求。
本案例不复制 token；它验证的是再次登录，而非共享同一份登录缓存。

## 关联问题

2026-09-26 线上实测：即使 deviceId 相同，第二次登录仍使第一次的凭据返回 401。
所以仅固定 deviceId 不能避免并行登录互踢。测试使用一个 worker；CI 共用账号并发组。
