# CLUB-005：申请、审批及邀请后的实际入会

## 目的与前置条件

P1，已部署 staging，桌面和手机。需要创建专用房主账号、`TESTING_API_TOKEN` 和测试注册接口。每例为普通申请和邀请申请分别创建独立账号；房主从 60 钻开始，本例创建俱乐部扣 50 钻。

## 步骤与预期

| 操作 | 预期 |
| --- | --- |
| 房主创建独立 E2E 俱乐部 | 创建响应含 UUID，成员初始为 1，实际扣 50 钻 |
| 申请人搜索本次名称、进入详情并申请 | 搜索、申请请求成功，按钮显示已申请；审批前成员列表没有该用户 |
| 房主在俱乐部通知中同意 | 该用户申请状态为已同意，服务端成员列表及申请人俱乐部列表均包含本次俱乐部 |
| 房主生成邀请链接，受邀者解析 code 并申请 | 链接解析为本次俱乐部申请；受邀者申请后仍不是成员 |
| 房主同意受邀申请 | 服务端成员列表包含房主、申请人、受邀者共 3 人 |
| 另一独立账号申请，房主拒绝 | 通知显示已拒绝，成员列表没有该账号 |
| 测试结束 | 仅移除本例加入的两个成员，成员数回到 1 |

## 定位契约

使用搜索结果 `search-club-item`、`club-search-item-touchable`、俱乐部加入按钮、`club-profile-item-touchable-club_notification`、`club-notification-item-<userId>` 和 `agree-button-<userId>`。所有审批均从房主 UI 发起；加入与成员状态用真实接口核对。邀请链接的生成、解析和申请使用与原生链接处理器相同的业务接口。

## 关联问题

当前 H5 没有原生应用的邀请链接接收入口，因此本例不声称验证 H5 点击邀请链接或原生跳转。俱乐部创建者尚无已核实的删除入口；E2E 俱乐部保留在 staging。测试账号也保留在 staging。申请发生后若后续失败，可能留下待审申请，测试不会操作其他用户数据。

2026-10-01 本地真实运行到邀请链接步骤时，`PUT /v1/share_link/generate` 返回 HTTP 404；本例因此失败，邀请申请和后续审批不能计为通过。搜索结果旧定位 `search-club-item` 未生成 DOM 元素，现已改为页面真实存在的 `club-search-item-touchable`，但这不解决邀请接口故障。
